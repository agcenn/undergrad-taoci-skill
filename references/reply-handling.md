# Reply Handling

Classify the professor's reply before drafting anything.

## Common types

### No opening / not taking students
Thank them briefly. Do not pressure them to reconsider.

### Requests CV / transcript / schedule
Answer the request directly and attach/provide only what is available.

### Asks about time commitment
Give the user's real availability. Do not invent hours.

### Invites a meeting
Help the user confirm time and, if requested, prepare for the discussion.

### Gives a trial task
Clarify deliverable, deadline, environment, and expected scope. Only then move into task planning if the user asks.

### Says the student may join
Help with the immediate reply. Afterward, the optional in-group workflow may be offered.

## Scope boundary

Do not automatically launch a full interview or onboarding workflow merely because a reply exists. Follow the user's requested next step.
